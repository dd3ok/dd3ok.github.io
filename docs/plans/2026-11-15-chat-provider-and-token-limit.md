# 채팅 제공자 전환과 긴 답변 대기

범위: 백엔드의 Gemini 3.8 Flash 채팅과 medium 추론, 최대 출력 8,192토큰에 맞춰 프로젝트 설명과 응답 대기 시간만 변경한다. Gemini 임베딩과 MongoDB 벡터 검색, 기존 채팅 이벤트 처리는 유지한다.

1. 프로젝트의 채팅 제공자 표기를 실제 연동과 맞춘다.
2. 백엔드 120초 제한 이후 오류를 받을 수 있도록 프런트 대기 시간을 150초로 조정한다.
3. 기존 검증·타입 검사·정적 빌드를 실행하고, 배포 후 실제 채팅과 후속 질문을 확인한다.

완료 기준: 새 API의 답변과 참고 자료가 표시되고, 생략형 후속 질문에서 같은 프로젝트가 유지된다. 응답 완료·오류 전에는 다음 질문 전송을 잠근다. API 키는 프런트에 넣지 않는다.

로컬 검증 완료: 프로토콜·세션 검사 5개, 데이터·설계·린트·타입 검사, 정적 빌드와 스모크 검사를 통과했다.

외부 API 검증: 크레딧 충전 후 Gemini 임베딩 HTTP 200·768차원과 Gemini 3.8 Flash의 medium 스트리밍 응답을 확인했다.

운영 반영 보류: 기존 요청에 따라 코드와 PR 준비까지만 진행한다. 별도 배포 요청 시 백엔드·프런트를 배포하고 재색인 및 실제 채팅·후속 질문을 검증한다.

추가 수정: 참고 자료 이벤트만으로 빈 답변이 생성되는 문제를 수정한다. 답변 목록에는 본문이 있는 응답만 반영하고, 참고 자료는 응답 상태에 보관한다. 공백 조각·첫 본문·완료·초기 실패·부분 실패를 이벤트 순서대로 회귀 검증하며 전송 잠금은 완료/오류까지 유지한다. 로컬 화면에서 로딩 표시와 답변 말풍선의 전환도 확인한다. 검증 후 기존 PR에 푸시하고 머지·배포는 진행하지 않는다.

추가 회귀 검증: 프로토콜·세션 검사 7개 통과. 내장 브라우저에서 로컬 WebSocket 테스트 서버로 SOURCES → 공백 DELTA → 본문 DELTA → DONE을 단계별 전송했다. 자료·공백만 있을 때는 로딩 행만 표시되고, 첫 본문 이후 답변 한 개로 전환되며, 다음 질문은 DONE 후에만 전송할 수 있었다. 두 번째 요청을 본문 없이 DONE으로 종료했을 때도 빈 말풍선 없이 오류와 재시도 버튼만 표시됐다. 테스트 서버는 로컬 메모리만 사용하며 운영 API나 DB는 변경하지 않았다.

최종 검증: `npm run build`로 데이터·설계·린트·타입 검사, 16개 정적 페이지 생성 및 스모크 검사를 통과했다. 로컬 테스트 서버와 개발 서버는 종료했다. 기존 PR #35에 커밋·푸시하며 머지와 배포는 보류한다.
